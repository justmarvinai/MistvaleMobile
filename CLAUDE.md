# CLAUDE.md — MistvaleMobile

**Mistvale** — a 2D pixel-art, turn-based champion-collection / gacha RPG in the browser, heavily inspired by Raid: Shadow Legends (structurally faithful, uniquely named, own numbers). Desktop-first, later landscape-mobile PWA. This repo: game client + authoritative server + battle engine + assets. Sibling repo `MistvaleMobile-Admin`: the operator SPA for the Admin API this server hosts.

## Project state
**Phases P0–P9 complete; P10 (release hardening) in progress** — see `ROADMAP.md`. The whole PvE game runs: a fresh account registers, picks a starter, walks the campaign map, fights a stage by hand or on auto or farms ten of it at once, and is paid for it — then equips what dropped, upgrades it, levels and ranks and ascends champions, trains masteries, shops, pulls at the Mistgate, and goes down into the Depths. Farm → equip → upgrade → stronger → farther is closed at every scale from 1-1 to the deepest keep floor.

Mistvale's four elements are registered into the library's own `AFFINITIES` table, which is how a component that takes an affinity *by key* can draw one the library has never heard of. Two things deliberately did **not** move: the mastery board, whose structure encodes three gating rules where `MasteryGrid` has one, and the four-column stat table, which teaches a piece of build literacy `StatsPanel` cannot say. **D5** is the relics and the economy around them: a relic is an `ArtifactCard` with roll pips on each substat, the paperdoll is nine painted sockets with the accessories dimmed until the ascension that opens them, and the champion sheet finally says what the pieces add up to — reading the server's own copy-aware description, because set bonuses stack in complete copies and a client-side count must never claim otherwise. Two helpers came out of it and are used everywhere: `relicArt` (nine slots, one icon and one glyph each, typed on `GearSlot` so a tenth cannot ship undrawn) and `championArt` (a drawn avatar when the asset declares one, a painted stand-in by faction otherwise — the gate is content's `avatarPath`, since nearly every champion points at the one art-pending model and "has an asset" answers nothing). **D6** is the world and the road through it: the campaign is a `WorldMap` of twelve chapters with the chosen one's stages snaking below it, a keep in the Depths is key art with a depth on it, the login calendar is a calendar, and an event's ladder is a rail with each rung at the score it is worth. Its own contribution to the kit is `ui/Ledger` — one component for every claimable objective in the game, because a daily quest, a step of the Path and a first win of the day are the same shape and were three lists that had already drifted — plus `ui/Empty`, `goalArt`, `dungeonArt` and `regionArt`. The defect it turned up was under every screen rather than on one: a panel stacked in a scrolling column was squashed to its header and drew its content behind the next panel, which is how the events screen had been losing its whole ladder. **D7** is the ladder: a rung is a `TierBadge` rather than two words, an opponent is four faces rather than four names, the ladder is the library's `Leaderboard` with its own metals on the top three, the Hall's four elements wear the affinity glyphs D4 registered, and the four champions a warden chose to be known by are the same painted cards the roster draws. `ui/arenaTier` is its contribution — Mistvale's ten rungs are a metal and a numeral, split once so the three places that draw one agree. The defect it fixed was the owner's: the rating stake overlapped the Challenge button, because a two-item row with no minimum on either side let a 9-sliced button push the numbers underneath itself. The rule that came out of it and governs the rest: **the library owns chrome, React owns behaviour** — where the library's component *is* the semantic element and holds no state React must drive, the component is used; where React owns the state, the art is used and the element stays ours. Gameplay and content are untouched by all of it. When the docs and reality diverge, fix one or the other in the same PR — stale docs are a review-blocker.

**Working on the code:** `pnpm install`, then `pnpm db:migrate` against a local PostgreSQL, `pnpm dev` to run server + client. `pnpm verify` runs the whole gate CI runs (format, lint, typecheck, test, build); `pnpm e2e` drives the browser flow. Server tests need PostgreSQL and skip themselves without it.

## Hard rules (from the owner's brief — non-negotiable)
- **Authoritative server.** The client never computes outcomes, rolls, or timers. All game math lives server-side (engine) — the client renders event logs and server numbers.
- **Content is data.** Champions/skills/items/stages/quests/events/constants live in PostgreSQL, edited via the Admin Suite. Adding content must never require code changes; every content field must be editable in Admin (no SQL-only knobs).
- **Production quality only.** No skeletons, MVPs, placeholders-as-architecture, or "temporary" hacks. Every phase ships finished, tested work.
- **Performance & maintainability first.** Target box: 1-core/4 GB VPS (budgets in ARCHITECTURE §9). Extensible module/screen patterns — "add more stuff" must stay the cheap operation.
- **No serif fonts. Anywhere.** Reaffirmed 2026-08-18 ("No Serife Fonts only Sans Serif"): the FantasyUIs display and body faces are Cinzel and Spectral, both serif, and `fui/mistvale.css` rebinds them to Mistvale's own `--mv-font-*` — which is where the game's type is decided, once.
- **No generic rounded "AI-slop" UI.** The game is dressed in **FantasyUIs** (`justmarvinai/FantasyUIs`, the owner's own library — painted 9-sliced panels, ornament frames, unit frames, turn meters), vendored into `apps/client/src/fui/` by `pnpm fui:vendor` and themed in `fui/mistvale.css`. **This replaces the hand-built pixel kit and the "no component library" rule**, both superseded by the owner on 2026-08-18 when the design rework was commissioned. The art is self-hosted (`setAssetBase('/fui')`) because nginx sends `img-src 'self'`. Never edit `src/fui/components|core|styles` — the next vendor overwrites them; Mistvale-specific work goes in `src/ui/` or the theme.
- **Icons only from game-icons.net** (via `tools/icon-fetch`, attributed) until custom icons exist. Never invent icons.
- **Assets:** only from `assets/` + the documented CC0/CC-BY sources in ASSET_GUIDE.md (owner holds rights to `assets/`). Track every third-party source in `CREDITS.md`.
- **Highly animated.** Idle loops always play; every action acknowledges within 100 ms; motion rules in UI_UX §1.2.
- **Auth:** account name + password + profile name. No e-mail anywhere; password resets happen via the Admin Suite only. One account system with ranks **Player / GameMaster / Admin** — only Admin rank can access the Admin Panel (`play.pathlands.cc/admin`).

## Conventions
- Server: feature modules `routes.ts / service.ts / repo.ts`; cross-module via services only; every mutation transactional with player-row lock; all grants through `RewardService` (→ `economy_log`); idempotency via `actionId`.
- Client: screen folders + registry; stores per domain; no game math client-side; pixel sprites integer-scaled, DOM UI free.
- Testing: engine = highest bar (mechanic units + golden replays + property tests); services tested against real Postgres in CI; goldens regenerate only in deliberate, reviewed commits.
- Commits: `feat(scope): …` / `fix:` / `docs:` / `chore:` / `test:`; CHANGELOG `[Unreleased]` entry for every player- or admin-visible change.
- Branches: **work on `main` and push there directly** (owner's standing instruction — no feature branch). Every push must leave `pnpm verify` and `pnpm sim` green, since nothing sits in front of `main`.
- Balance numbers: never hardcode — they live in `game_config`/content seeds (ECONOMY_BALANCE.md documents defaults).
