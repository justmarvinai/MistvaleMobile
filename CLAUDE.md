# CLAUDE.md — MistvaleMobile

**Mistvale** — a 2D pixel-art, turn-based champion-collection / gacha RPG in the browser, heavily inspired by Raid: Shadow Legends (structurally faithful, uniquely named, own numbers). Desktop-first, later landscape-mobile PWA. This repo: game client + authoritative server + battle engine + assets. Sibling repo `MistvaleMobile-Admin`: the operator SPA for the Admin API this server hosts.

## Project state
**Phases P0–P10 complete — the game is live on the owner's box and multiple people play it (2026-08-27); the design rework D0–D9 closed and the owner's change batches (B, C) running on top** — see `ROADMAP.md`. The whole PvE game runs: a fresh account registers, picks a starter, walks the campaign map, fights a stage by hand or on auto or farms ten of it at once, and is paid for it — then equips what dropped, upgrades it, levels and ranks and ascends champions, trains masteries, shops, pulls at the Mistgate, and goes down into the Depths. Farm → equip → upgrade → stronger → farther is closed at every scale from 1-1 to the deepest keep floor.

Two sketched components were not built and should not be: `DepthsKeep` was answered by the library's `EventBanner` in D6, and `MistScene` is decoration over a backdrop that already exists. **D9** closed it: a sweep of every screen, the §9 budgets re-measured with the art in, and the last two layout bugs — both the same one, a fixed-width library card in a stretched holder, so the Forge and Lock buttons drew wider than the relic they belong to and four profile champions stacked one per row. `$card-artifact` and `$card-champion` are tokens now. The guard took four attempts to make honest: measuring overflow finds neither bug, measuring the React bridge measures a `display: contents` box with no size, and measuring every holder flags every grid — what survives is that a holder laying out a card *and something else* must be the card's width, and it refuses to pass if it measured no cards at all. The budget answer is that the whole library layer costs 20 KB gzipped; the champion avatars, published untouched at 1254px and drawn at 150, cost 14 MB and are Q6. The rule that came out of it and governs the rest: **the library owns chrome, React owns behaviour** — where the library's component *is* the semantic element and holds no state React must drive, the component is used; where React owns the state, the art is used and the element stays ours. Gameplay and content are untouched by all of it. **D is closed.** · **the owner's change batches** (B, opened 2026-08-19) — the rework's follow-up, one pass per batch with the whole gate green behind it. **B1** fixed the calendar (claiming one day marked all thirty collected: the library's grid counts *tiles*, the screen was handing it a day number with a `days.length + 1` fallback that fired the moment today's claim was spent — `trackTiles` names the two states separately and derives both from the server's own per-day flags) and gave every screen its frame back. The governing rule of the batch, and of every screen added after it: **a screen is the feature, not the feature and a column about it.** *Words* go behind an **i** in the title bar (`ui/ScreenInfo`); anything a player can **act on** stays and finds a home in the layout — the Bazaar's crystal buttons with the restock clock, the Vault's meter and actions as a toolbar with its selection as a bar across the foot, the Arena's defence and chest in the standing strip with the Hall and the ladder in the title bar, the first-win rail across the top of Errands, the springs' week with the springs. Published gacha odds are the one exception to the icon — a worded **Odds & mercy** button, because nobody should have to guess which icon hides the rates. The title itself is one quiet line with the tagline beside it and no divider, and its `actions` slot is where screen-level controls live now. With the columns gone the campaign map fills the pane it is in rather than a computed 420px, the Haven's stations grew and centred, and the profile chip's level ring — a shape that can say "some of the way" and nothing else — became a real bar under the name carrying the two numbers a player counts. · **B2** was the battles. The headline is that **the champions were not on the battlefield** — the owner's fights drew a full HUD, a turn order, moving health bars and an empty field — and it was two faults at once. `attachSprite` returned when no frame loaded, so *any* art problem arrived as an invisible battle rather than a plain-looking one; and nothing in the deploy ever checked that the sprite tree shipped, which is a failure with no symptom anywhere except the one place nobody could test. Both are closed: a unit falls back to the shared silhouette and then to a drawn figure, so no state of the world leaves a slot empty; `UPDATE.sh` refuses a release with no `sprites/manifest.json` and `STATUS.sh` counts the units in the running one. **And the suite can see the canvas now** — `e2e/pixels.ts` decodes a screenshot in about eighty lines of zlib and PNG line filters, so `visible.spec.ts` can ask how much of the field is not the ground, with art and with every sprite request refused. With it: the stage dialog drew outside its own frame (a 30rem body in a 480px modal, so the action rows went through the ornament — 720 now, and each row is a sentence that yields beside a button that does not); **the game remembers** (`state/loadoutStore.ts` — the last team per *battle mode*, filtered to champions still owned, plus speed and Auto as standing choices rather than per-fight ones, with Auto finally a real toggle); one placeholder for every faceless champion instead of a different painted library hero per faction, because eight borrowed heroes read as eight different games; and painted tooltips (`ui/Tooltip/useTooltip`, which adds focus/blur and clears the native `title` so the browser's grey box does not land on the painted one). · **The empty battlefield** took four rounds and was worth every one: `initStage` handed back an application without checking which `<canvas>` it had been built for, so a remount landing mid-init left it drawing into a node that had left the document — invisible field, perfect HUD, and a race that reproduced on the owner's machine and never here. `game/stage.ts` now owns a canvas, survives an unmount that is really a remount, never removes React's view, and reports a missing graphics context instead of rejecting into nothing (`game/stage.test.ts`). Alongside it: the battle screen's blank-field notice names which of four causes it is, so a screenshot is a diagnosis; `WaveTracker` gets an `apply` and finally leaves wave one; the turn-order strip is gone at the owner's request; `tools/fui-vendor` prunes `assets.css` to the art it vendored, which is where twenty-eight build warnings a build were coming from; and **the battlefield has a second renderer** — `DomBattlefield`, the same view and the same formation drawn as DOM, used on the player's **Simple battlefield** switch and automatically when there is no graphics context, because a machine can hand back a context that draws the allies and not the enemies and nothing in the page can tell. · **And then the actual cause turned up**, five rounds in, in Mistvale's own nginx config: Pixi builds its shaders with `new Function` and the site sends `script-src 'self'`, so `Application.init` rejected with *"does not allow unsafe-eval"*, every scene was held pending, and the DOM half of the game carried on perfectly. It never reproduced here because **the dev server sends no CSP at all** — the one environment nobody could test was the only one where it happened. `game/stage.ts` imports `pixi.js/unsafe-eval` (loosening the policy was never on the table) and `e2e/csp.spec.ts` serves the *real build* under the policy parsed out of the deployed nginx config, so this class of bug fails in CI now. With it: `game/facing.ts`, because "mirror the enemy side" is only right if all art faces one way and enemy art is authored already facing the party — both renderers ask one function now; damage numbers moved to the library's `FloatingText` at the owner's suggestion, which fixes numbers landing inside the champion and simultaneous hits stacking; and the DOM battlefield idles at the art's own nine frames a second. · **B3 gave the fight its decisions back.** Everything it needed had been in the engine's contract since P3 and none of it had reached the screen: skills now say who they land on, what they cost in turns and when they return; buffs and debuffs are blue and red chips carrying their turn count and their own words; the player picks the target, and the same click tells auto-battle where to concentrate (a preference the engine declines where the skill leaves no choice, never an order). The two bugs under it were real: **Auto could be switched on and never off**, because `auto: true` resolved the whole fight server-side and there was nothing left to cancel — the engine takes an `autoTurns` bound now and the button asks for eight at a time, re-asking only while the playback queue is short, because pacing it to the animation makes Auto as slow as watching and letting it run unbounded is the original bug in a new coat. Skip is the other half: it is offered for the whole of an auto-battle now and it *finishes* the fight rather than jumping two seconds forward — Auto is the toggle, Skip is the commitment, and they share one wire (`state/oneAtATime.ts`) so neither can slice the event log at a length the other has moved past — and the **ground stopped at the letterbox**, because the scene contains its 960×540 canvas and the floor was drawn exactly that wide — guarded now in a deliberately wide window, since at the suite's usual 1440×900 the field fits exactly and the bug is invisible. `UnitOverlay` is the pattern worth keeping: the battlefield is painted, the decisions are DOM, one thin layer over whichever renderer is running. · **B4 was the tutorial, and the first audio the game has ever had.** The owner's pack — two music tracks, twelve of the fifteen Wardenmaster lines, and his portrait — arrived as files in `assets/`, and all of it is content: `soundCue.sample`/`.loop` for the music, `tutorialStep.portrait`/`.sound` for the tutorial, so swapping any of it is an edit in Admin. `audio/tracks.ts` is the split that made it work — `mixer.ts` renders cues from parameters and fires them a thousand times; a track is one file at a time, streamed, looped, replaced rather than layered, and crossfaded because swapping a seven-minute loop with a hard cut is the most noticeable thing an audio layer can get wrong. Which track plays follows the screen and nothing else, since every fighting mode in the game runs on the battle screen. The Wardenmaster's line is cut the instant its step closes, because a voice still explaining relics over the next beat is worse than no voice; three steps have no recording and are read instead, which is the design. Both obey sliders that already existed — music on the music bus, the Wardenmaster on effects, since somebody who muted the soundtrack still wants to be told what to do. With it: **the overlay stopped dimming the game** (it pointed by cutting a hole in a scrim, so the art greyed out and a narrated fight was watched through a filter — the ring was carrying the job anyway, so it got heavier and the panes went), the card **can be dragged** (`ui/useDraggable.ts`; title row is the handle, arrow keys nudge, clamped so it can never be lost off-screen) because a card that points at things eventually points at something underneath itself, and `pnpm assets` learned to publish finished media under its own filenames — gitignored like the sprites, only more so, since the two tracks alone are 16 MB. · **C1 was five reports and two causes.** The worst was that **a reload mid-fight bricked the account**: the screen is a value in a store rather than a URL, so a reload lands on the Haven, and `BattleScreen` is the only thing that ever asked the server to resume — after a reload it never mounted, the session stayed active forever, and everything the player pressed afterwards answered "You are already in a battle" about a fight they could not reach. It took an operator to undo. The shell resumes on sign-in now, a refused start resumes rather than dead-ends, and `enterFrom` gives a resumed fight the room it belongs to so "Back to the campaign" goes there. · The other four were mostly **one bug in the React bridge**: `liveCallbacks` keeps a component's handlers live through `optionsRef`, but that ref was only refreshed inside the effect keyed on `shallowKey(options)` — and `shallowKey` skips functions, so a render changing only a closure never refreshed it. The Feed button's one other moving prop is `disabled`, which flips on the *first* pick, so every later pick left the handler behind and feeding four champions spent one. It looked like a broken feed and was a broken bridge under every painted control in the game. With it, the call sites that never pushed a change through a setter: the top bar's level numeral (the XP *bar* had an `apply`, the numeral did not — which is the "only updates on reload" report), the champion sheet's relic sockets, and for the whole of a fight the party's health bars, the unit plates and the hotbar's cooldowns; plus a keyed rebuild for the three components the library gives no setters at all (a forged relic's level, the set bonuses it completes, the collection tally). · Forging a worn relic was never refused by the server — the only Forge button lived in the vault, whose default filter excludes everything a champion is wearing — so the slot's own panel offers it now. · And the champion sheet got the room `UI_UX §3` had specified all along: 1160px and two columns, with `ui/ChampionIdle` standing the champion in their own sheet — the third idle loop in the game and the first outside a fight, DOM rather than a third Pixi surface because a modal should not take a graphics context the battlefield may want back. · **C2** was the collection's furniture: every champion picker in the game draws the same painted card the roster does, every dialog got the room its content asks for, and the Mistgate became a place worth going to — a pull that teases before it pays. · **C3** made the game explain itself: painted tooltips on everything worth hovering (equipped relics, battle rewards, stats), an equipped relic showing its rarity as a coloured frame rather than only in a line of text, the tutorial's fifteen bodies rewritten so each says what to do as well as what it means — the steps and their goals untouched — and the Chronicle rebuilt as a **faction index that hides nothing**, every champion in the game on a shelf with their real face and name, the ones you do not hold simply grey. Its operational half is `SEED.sh --replace <type>`: the default seed only *adds*, so a rewrite of already-published content had no way to ship, and the fix had to run **after** the field-backfill rather than before it, or the backfill wrote the pre-replace row straight back over it. · **C4** is the two screens a player spends the most time on. The **Haven** is a horizontally draggable rail of tall painted boards instead of twelve 64px sockets in a grid — each with its own art, its name and the line saying what a player goes there *for*, which used to live only on a hover and so was unreachable on a phone. Touch is left to the browser (`touch-action: pan-x`) so a finger gets the platform's own inertia and snap; pointer events drive mouse and pen only, and the click a drag ends with is eaten in the capture phase. `ui/Rail` is general, and its arithmetic — drag threshold, flick decay, snap points, both ends — is pure and tested. The **campaign** became three screens: the vale fills the window; a chapter is a page of its own where each stage is a **row** carrying its stars, the set the chapter farms, the slots that stage drops, its wave count, its cost and the best turn count ever managed on it, beside a brief naming the warlord and the star-chest track; and the team chooser now shows **the enemy line-up wave by wave** before any energy is spent. Which chapter is open lives in a store rather than in the component, because a fight unmounts the campaign and every victory used to drop the player back on the world map, several clicks from the stage they were about to run again. · **C5** is the top bar. It was the library's phone-width defaults on a desktop window — 12px text, 17px coins, 30px buttons and a 38px disc with an initial in it — so everything on it grew, and **the player chip became Mistvale's own** (`ui/ProfileChip`): a framed portrait with the level on its corner, the name at a readable size, the account's power and the experience bar with both numbers beside it. The library still paints the ground, the currency rail and the tool buttons, which is chrome; the chip is ours because every part of it is state React drives, and it is portalled onto the same leather rather than built beside it. **The portrait is a champion you own**, chosen on your own card in one press and stored as `players.avatar_champion_key` — a champion *key* rather than a roster id, which is the difference between it and the showcase beside it: the showcase presents a particular copy at its level and rank, a face is a face, and feeding away one Anuria of three must not blank a portrait. The server checks the key resolves, is not food, and is held; it deliberately does not re-check on read, because a portrait that vanishes untouched is worse than one that outlives its copy. Power is the four strongest added together — a team you could field rather than a total that rewards hoarding. · **C6** is champion progression, rebuilt to the source game's shape with one deliberate difference: **the star track belongs to the rarity rather than to the champion**. A Common keeps the star it was called at and never moves — which is what makes it food rather than a project — an Uncommon and a Rare climb to ★5, an Epic and a Legendary to ★6, and 60 is the level anybody's road ends at, with the cap following the star (20/20/30/40/50/60) and a rank-up resetting to level 1 against the new one. Rare and above ascend and awaken. The ceilings are a *rule* in `packages/shared/src/progression.ts` rather than a tunable, so a Common cannot be authored into a six-star; what is content is where a champion is **called** (`champion.baseRank`, defaulting to the bottom of its rarity's band). With it **Mistbrew**, the one XP consumable — not one per element, because the source game's four-way split turns levelling into inventory sorting — poured on the same dialog that chooses food; and **awakening**, the fourth ladder and the last thing left to do to a champion, gated on the star ceiling then the level cap then a full ascension, paid in **Waking Shards** that fall in the back half of the Depths and nowhere else. The champion sheet is four ladders now instead of three buttons hiding their reasons in a native `title` — one shape drawn four times, and a ladder the rarity never had drawn dashed and buttonless, because there is nothing to press now or ever. Two things it turned up: the sheet had **never read what the player was holding** (the inventory store is filled by the relic screens, so every material cost was priced against an empty list — wrong since ascension shipped, invisible until levelling started spending items), and the seed's fill **cannot reach nested fields**, so C6's brew and shard published as items and then dropped nowhere until `SEED.sh --replace stage,dungeon,shop` ran — which DEPLOYMENT_OPERATIONS §5 now names as a release step. The browser suite then caught a third, and it was C5's: the top bar reads the roster now (the account's power is the four strongest added together) and it sits **outside** the screen's error boundary, so one malformed roster response took down the frame the boundary exists to keep standing — dock and all. There are three boundaries now rather than two, and the chrome's is quiet and reset by navigation rather than keyed to it. · **C7** is two rules about *watching* a fight, both the owner's: **Skip is offered only on a stage already beaten** — decided when the fight opens and stored on the battle, because by the time the last turn resolves `recordClear` has run and a recomputed answer would be about the clear this very fight produced; the Arena is exempt since its stage key is an opponent rather than a place — and **playback runs ×1–×4** (`battle.speedUnlocks`, an unnamed speed meaning "open to everybody" — the ladder's shape settled in C8, below). ## Hard rules (from the owner's brief — non-negotiable)
- **Authoritative server.** The client never computes outcomes, rolls, or timers. All game math lives server-side (engine) — the client renders event logs and server numbers.
- **Content is data.** Champions/skills/items/stages/quests/events/constants live in PostgreSQL, edited via the Admin Suite. Adding content must never require code changes; every content field must be editable in Admin (no SQL-only knobs).
- **Production quality only.** No skeletons, MVPs, placeholders-as-architecture, or "temporary" hacks. Every phase ships finished, tested work.
- **Performance & maintainability first.** Target box: 1-core/4 GB VPS (budgets in ARCHITECTURE §9). Extensible module/screen patterns — "add more stuff" must stay the cheap operation.
- **No serif fonts. Anywhere.** Reaffirmed 2026-08-18 ("No Serife Fonts only Sans Serif"): the FantasyUIs display and body faces are Cinzel and Spectral, both serif, and `fui/mistvale.css` rebinds them to Mistvale's own `--mv-font-*` — which is where the game's type is decided, once.
- **No generic rounded "AI-slop" UI.** The game is dressed in **FantasyUIs** (`justmarvinai/FantasyUIs`, the owner's own library — painted 9-sliced panels, ornament frames, unit frames, turn meters), vendored into `apps/client/src/fui/` by `pnpm fui:vendor` and themed in `fui/mistvale.css`. **This replaces the hand-built pixel kit and the "no component library" rule**, both superseded by the owner on 2026-08-18 when the design rework was commissioned. The art is self-hosted (`setAssetBase('/fui')`) because nginx sends `img-src 'self'`. Never edit `src/fui/components|core|styles` — the next vendor overwrites them; Mistvale-specific work goes in `src/ui/` or the theme.
- **Icons only from game-icons.net** (via `tools/icon-fetch`, attributed) until custom icons exist. Never invent icons.
- **Assets:** only from `assets/` + the documented CC0/CC-BY sources in ASSET_GUIDE.md (owner holds rights to `assets/`). Track every third-party source in `CREDITS.md`.
- **Highly animated.** Idle loops always play; every action acknowledges within 100 ms; motion rules in UI_UX §1.2.
- **Auth:** account name + password + profile name. No e-mail anywhere; password resets happen via the Admin Suite only. One account system with ranks **Player / GameMaster / Admin** — only Admin rank can access the Admin Panel (`play.pathlands.cc/admin`).

## Conventions
- Server: feature modules `routes.ts / service.ts / repo.ts`; cross-module via services only; every mutation transactional with player-row lock; all grants through `RewardService` (→ `economy_log`); idempotency via `actionId`.
- Client: screen folders + registry; stores per domain; no game math client-side; pixel sprites integer-scaled, DOM UI free.
- Testing: engine = highest bar (mechanic units + golden replays + property tests); services tested against real Postgres in CI; goldens regenerate only in deliberate, reviewed commits.
- Commits: `feat(scope): …` / `fix:` / `docs:` / `chore:` / `test:`; CHANGELOG `[Unreleased]` entry for every player- or admin-visible change.
- Branches: **work on `main` and push there directly** (owner's standing instruction — no feature branch). Every push must leave `pnpm verify` and `pnpm sim` green, since nothing sits in front of `main`.
- Balance numbers: never hardcode — they live in `game_config`/content seeds (ECONOMY_BALANCE.md documents defaults).
